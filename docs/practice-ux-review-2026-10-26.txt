코칭 UX / 재생 성능 수정 — 운영 배포 완료

원인
- 임팩트 응답의 hash가 도착하면 video src/key가 달라져 영상 재로드, 자동 후보 seek 발생.
- metadata preload 및 드래그 중 연속 seek가 느린 네트워크에서 사용자 조작 지연을 키움.
- 2.28MB 영상: Pi 내부 HTTP 1MB 10ms, 개발 머신 SSH 전송 전체 24.29초. 사용자의 iPhone 네트워크는 직접 측정하지 않음.
- 준비 0ms는 주변 표본이 부족할 수 있는데 사용자는 두 장면 선택/확인을 완료한 뒤에야 보류를 받음.

변경
- 영상 URL을 job 기준으로 유지. 임팩트 결과 도착 시 자동 점프 제거.
- 영상 자동 preload, 드래그 종료 때 한 번 seek, buffering 표시.
- 640px 이하 H264 재생본을 저장·재사용. 원본 화질 전환 가능.
- 한 번에 변환 하나/동일 파일 중복 제거/실패 시 원본. 원본 분석·라벨·추론 데이터는 변경하지 않음.
- 원본 timebase 및 프레임 시점 유지. 첫 재생본 생성에는 수 초가 들 수 있음.
- 기존 자세에서 가까운 비교 가능 구간을 사전 탐색. 각도 변화가 큰 구간을 우선 고르지 않음.
- preview endpoint는 장면 후보만 반환. 수치/코칭/연습을 반환하지 않음.
- 사용자가 두 장면을 보고 비교를 눌러야 코칭 API 실행. 체크박스/수동 저장은 기본 흐름에서 제거.
- 코칭 카드를 영상 바로 아래로 이동. 직접 조정은 접어둠. 측정 불가와 연결 오류 구분.
